# Olist CRM — acquisition and linked seller value

An Excel case study built from two real, anonymized datasets published by Olist. It asks which recorded acquisition sources and observed won cohorts are associated with seller onboarding, closing speed and merchandise value visible in a linked sample.

Open **Olist_CRM_Acquisition_Seller_Value.xlsx**. Start at Dashboard, then inspect Channel_Performance, Rep_Performance, Monthly_Trend and Seller_Value. Lookups contains two amber review controls. Source IDs, missing values and chronology exceptions remain traceable.

## Data and baseline

- 8,000 sampled MQLs and 842 recorded won deals: recorded won share 10.525%.
- 841 valid calendar-day closing intervals; median 14 days. One won-before-contact record remains in won counts but is excluded from time metrics.
- 380/842 won sellers match order items in the separate sample; 376 match eligible Delivered activity after their won timestamp.
- 4,984 eligible items; 4,463 seller-order links across 4,457 distinct global orders.
- Eligible recorded item prices sum to 664,858.00 original price units, excluding freight. This is not Olist revenue, profit, lifetime value or CRM deal value.
- 60 missing origins remain distinct from 1,099 literal `unknown` source labels.

The raw source files have not been generated by AI or changed. Analytical mappings, thresholds, formulas and prose are project work. AI assisted artifact construction and checking; the artifact does not establish independent authorship or interview mastery.

## Scope

No won record does not establish Lost/Open status. Rep IDs occur in the won table only, so rep win rates and quotas are not measurable. Calendar wins and contact-cohort outcomes have different date bases. Follow-up and sample linkage differ across sources/cohorts. No causal marketing effect, ROI, measured uplift or forecast is claimed.

Publisher pages reviewed do not explicitly specify a currency code for the CSV `price` field. Values are therefore reported in original recorded price units without relabelling them USD or applying FX. Seller-declared monthly revenue is preserved, but its 797 zeros are not assumed to be observed zero revenue.

## Reproduce

1. Keep the five CSVs in `data/source` unchanged.
2. Install the dependencies in `requirements-analysis.txt` in an isolated local environment.
3. Run `python analysis/run_analysis.py` from this folder. It rechecks keys/schema, reproduces prepared inputs and analytical CSVs, and writes hashes and summary JSON in `analysis/outputs`.
4. Optional full XLSX reconstruction uses `python analysis/rebuild_in_codex.py` in a Codex primary-runtime environment with `@oai/artifact-tool`, LibreOffice and the Python dependencies listed in `requirements-rebuild.txt`. This entrypoint builds bounded fragments and applies the layout repair. Do not run the whole-data `build_workbook.mjs` directly: whole-workbook authoring exceeded memory during the original build. Installing pandas alone reproduces the analysis, not the XLSX authoring engine. Full reconstruction has not been rerun during this takeover; the delivered workbook repair and analytical fresh-run have been tested.
5. Recalculate the delivered workbook with Microsoft Excel. Follow `docs/MICROSOFT_EXCEL_CHECKLIST.md`.
